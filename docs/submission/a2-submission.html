External intelligence for IT operations

InfraRisk Analyzer

Review infrastructure changes before they become outages.

InfraRisk Analyzer extends the Assignment 1 Change Review Board with request-time External Intelligence. An Operator selects a locally stored IT Change, searches NVD by vendor/product, or enters a known CVE. The application retrieves technical evidence from the NVD JSON API and an exploitation/remediation signal from the CISA Known Exploited Vulnerabilities catalog.

Boundary: External evidence informs human review. It does not prove that the selected Affected System is vulnerable, change the manually assigned Risk Level, approve or block the IT Change, or create a persistent source record.

API source

NVD API 2.0 returns the English description, publication date, best CVSS metric, and record URL.

Scraped source

CISA's public KEV table contributes vendor, product, vulnerability, dates, and required action.

Unified purpose

Both sources answer what current vulnerability evidence an Operator should consider before a change window.

Acquisition and integration workflow

One review, two external evidence boundaries

Operator selects Change Ticket + enters vendor/product→NVD keyword search returns possible CVEs→Operator selects a candidate→CISA catalog HTML request
Extract relevant JSON fields→Parse, clean, exact-match table row→Combine evidence with local IT Change→Guided human interpretation

Reflection and next steps

Ethics, limitations, and Assignment 3

Ethical considerations

  • Attributes NVD and CISA and links to their source records.
  • Uses the documented NVD endpoint, API key header, descriptive User-Agent, finite timeout, and respectful request frequency.
  • Scrapes only public CISA table fields needed for review; respects source terms, licensing, robots guidance, and layout changes.
  • Does not collect personal information or infer compromise from a CVE match.

Known limitations

  • Evidence is request-time and process-local CISA caching is lost on restart.
  • External schemas, availability, rate limits, and HTML layout can change.
  • A CVE does not establish that the selected system uses the affected product/version.
  • Demonstration data is not a production approval system.

Assignment 3 direction

Add persistent IT Changes, Risk Findings, Approval Records, Audit Trail events, and timestamped External Intelligence Snapshots. A snapshot will retain the normalized NVD/CISA evidence, source URLs, retrieval timestamps, selected Change Ticket, and Operator review context without turning external evidence into automatic approval or blocking logic.
